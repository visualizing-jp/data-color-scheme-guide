## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。講義スライド「データの性質を表現する色の考え方」をもとに、「色相は種類の違いを、明るさ（明度）は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人です。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 を同梱）で、図・共有モジュール・本文を、担当ごとに互いのファイルに触れずに並行して作っています。最初に `README.md` を読んでください。図の契約、担当範囲、共通の操作部品、動かし方が書いてあります。

あなたの作業ブランチは `w1/wa-cone-explorer`（`s0/skeleton` から分岐）です。

## 仕事
第1章「色が見えるしくみ」の図 `widgets/cone-explorer/` を作ります。`widgets/_template/` をひな形にしてください。読者に伝えたいことは2つです。
1. 目の中には L・M・S の3種類の錐体があり、光の波長によって、それぞれの反応量が変わる。色は、この3つの反応量の組で決まる。
2. 成分の違う光でも、3つの反応量が同じなら同じ色に見える。だから画面は、赤・緑・青の3色の光で多くの色を作れる。

### 図の構成（上から順に）
**第1部：波長を動かす**
- 見出し「波長を動かして、3種類の錐体の反応を見る」と、リード文「光の波長を変えると、L・M・Sの錐体の反応量が変わります。」
- スペクトルの帯（390〜700nm）と、その上に重ねた L・M・S の感度曲線。曲線は赤・緑・青に塗らず、グレーの濃淡と線種（実線・破線・点線）で区別し、線の端に「L」「M」「S」の文字ラベルを付けます（「Lは赤」という思い込みを避けるためです）。各曲線の感度が最大になる波長に、薄い縦線とラベル（データから求めた値）を付けます。
- 波長スライダー（390〜700nm、5nm刻み、初期値580nm）。帯の上に現在の波長を示す縦線を出し、帯の横に「この波長の光（画面での近似表示）」の色見本を出します。
- L・M・S の反応量を示す3本の横棒と数値（小数2桁）。数値の横に、やさしい言葉での量の表現を添えます（0.05未満「ほとんどなし」、0.05〜0.35「すこし」、0.35〜0.7「そこそこ」、0.7以上「たくさん」）。

**第2部：2つの光を混ぜる**
- 見出し「ちがう光でも、同じ色に見える」と、リード文「黄色の光（580nm）と、緑の光（550nm）＋赤い光（630nm）。成分は違いますが、混ぜ方しだいで錐体の反応量はほぼ同じになります。」
- 左：黄色の単色光（580nm、強さ1）の L・M・S の反応量。右：緑の光（550nm）と赤い光（630nm）を混ぜた光の L・M・S の反応量。右側には「緑の光の強さ」のスライダー（0〜1、0.005刻み、初期値0.2）があり、赤い光の強さは1で固定です。
- 左右の反応量を、同じ目盛りの横棒で上下に並べて比べられるようにします。
- 判定の表示（`.verdict`）：L と M の差がどちらも 0.02 以下のとき「反応量がほぼ同じ → 同じ色に見えます」、それ以外は「まだ違います」。
- ボタン「ぴったり合わせる」（緑の光の強さを 0.605 にする）と「最初に戻す」。
- 図の下の注（`.fig-note`）：「錐体の感度は Stockman & Sharpe (2000) の2°錐体分光感度（エネルギー基準、各錐体の最大値を1に正規化）によります。画面では、単色光の色を完全には再現できません。色見本は近似です。」

### データ
`widgets/cone-explorer/cones.json` に、下の「cones.json」の内容をそのまま置き、mount の中で `new URL('./cones.json', import.meta.url)` から fetch します（mount は async にします）。このデータは、調査担当が Python パッケージ colour-science から取り出して検算したものです。取り出しの手順と検算値、帯の色の求め方、混合の数値の根拠は、下の「調査結果」にあります。帯は JSON の `band`（波長ごとの色）を使って描きます。

```python
# make_cones.py
import json
import numpy as np
from colour.colorimetry.datasets.cmfs import DATA_CMFS_LMS, DATA_CMFS_STANDARD_OBSERVER
LMS = DATA_CMFS_LMS["Stockman & Sharpe 2 Degree Cone Fundamentals"]   # 1nm表をそのまま引く（補間しない）
XYZ = DATA_CMFS_STANDARD_OBSERVER["CIE 1931 2 Degree Standard Observer"]
WL = list(range(390, 701, 5))
M = np.array([[3.2406, -1.5372, -0.4986], [-0.9689, 1.8758, 0.0415], [0.0557, -0.2040, 1.0570]])  # XYZ→線形sRGB（D65）
def encode(c): return np.where(c <= 0.0031308, 12.92*c, 1.055*np.power(c, 1/2.4) - 0.055)
def band_rgb(w):
    rgb = np.clip(M @ np.array(XYZ[w]), 0, None)        # 色域外：負の成分を0に切る
    rgb = rgb / rgb.max() if rgb.max() > 0 else rgb     # 最大の成分を1にそろえる
    return "#" + "".join(f"{round(float(v)*255):02x}" for v in encode(np.clip(rgb, 0, 1)))
r = lambda v: round(float(v), 6)
out = {"source": "Stockman & Sharpe (2000) 2-deg cone fundamentals (linear energy, peak=1), via colour-science 0.4.7; CIE 1931 2-deg CMFs via colour-science",
       "wavelengths": WL,
       "L": [r(LMS[w][0]) for w in WL], "M": [r(LMS[w][1]) for w in WL], "S": [r(LMS[w][2]) for w in WL],
       "xbar": [r(XYZ[w][0]) for w in WL], "ybar": [r(XYZ[w][1]) for w in WL], "zbar": [r(XYZ[w][2]) for w in WL],
       "bandColor": [band_rgb(w) for w in WL]}
print(json.dumps(out, separators=(",", ":")))
```
注意：`MSDS_CMFS_LMS[...][616]` のように整数でない位置や表にない波長を引くと補間値が返る（616nm の S は -8e-22 になった）。そのため、表の値をそのまま使える `DATA_CMFS_LMS`（辞書）から引く。

## 4. スペクトルの帯（波長→画面の色）
推奨する手順は、x̄ȳz̄ → IEC 61966-2-1 の行列で線形sRGBに変換 → **負の成分を0に切る** → 最大の成分で割る（明るさの情報は捨て、色相だけを見せる）→ sRGBのガンマ（0.0031308 を境目にした区分関数）。色はビルド時に計算して JSON の `bandColor` に持たせ、ブラウザ側では計算しない。
- 色域外の扱いとして「負の成分が0になるまで白を足す」方式も試したが、620nm より長い側が桃色（#ff0055）に転んだため採用しなかった。【実行確認】
- 0に切る方式では 515〜550nm が #00ff00、610nm 以降が #ff0000 と同じ色になる（単色光はsRGBの色域外なので避けられない）。
- 両端を暗く見せたい場合は任意で、390〜420nm と 645〜700nm で線形RGBを 0.3→1 に漸増させる係数を掛ける（見た目のための処理で、物理的な根拠はない）。
- 根拠となる一次情報：sRGB の規格は IEC 61966-2-1:1999 で有料のため【未閲覧】。行列とガンマの数式は https://www.w3.org/Graphics/Color/srgb にある、という記憶に基づく【未確認】。CIE 1931 の表は https://cie.co.at/datatable/cie-1931-colour-matching-functions-2-degree-observer にある、という記憶に基づく【未確認】（どちらも今回は開いていない）。

## 5. 「混ぜると黄色」の数値例【実行確認】
2つの単色光の強度 a, b（エネルギー単位。黄色の光を1としたときの比）を、2×2の連立方程式 a·L(g)+b·L(r)=L(y)、a·M(g)+b·M(r)=M(y) を解いて求めた。

| 黄色 y | 緑寄り g | 赤寄り r | a | b | 混合光のS − 黄色のS |
|---|---|---|---|---|---|
| **580** | **550** | **630** | **0.6050** | **0.9998** | **+0.0011** |
| 580 | 545 | 620 | 0.5589 | 0.8223 | +0.0017 |
| 580 | 550 | 650 | 0.6327 | 2.2684 | +0.0011 |
| 580 | 540 | 640 | 0.6045 | 1.6436 | +0.0030 |
| 575 | 550 | 630 | 0.7054 | 0.8214 | +0.0012（緑と赤の比は異なる） |
| 589 | 545 | 670 | (参考：アノマロスコープの組合せ。b が10倍を超えるため不向き) | | |

**推奨：550nm（緑）×0.605 ＋ 630nm（赤）×1.00 ＝ 580nm（黄）。** 赤の強度がほぼ1で説明しやすく、帯の色も緑 #00ff00、赤 #ff0000、黄 #ffb400 とはっきり分かれる。S の差は 0.0011 で、S のピーク（1）の 0.1% にあたる。目には見えない差なので、「S はどちらもほぼ0」と説明すればよい。
同じ a, b を CIE 1931 の XYZ に当てはめると、混合光は xy=(0.5091, 0.4879)、黄色は xy=(0.5125, 0.4866) になる。どちらも描画すると #ffb600 と #ffb400 になり、ほぼ同じ色である。

## 6. 受入条件の案
- `cones.json`：390〜700nm の63点。450・550・600nm の L/M/S が上の表と小数4桁で一致すること。各系列の最大値が 0.9999 以上 1.0001 以下であること。S は 620nm 以降が 0 であること。
- 混合：a=0.605、b=1.000（または図の中で連立方程式を解く）のとき、|ΔL| と |ΔM| がどちらも 0.001 以下であること（3桁に丸めた a, b での実測値は ΔL=1.0e-4、ΔM=4e-5）。|ΔS| は 0.002 以下であること。
- 読者が強度スライダーを操作する場合：|ΔL|/L(y) と |ΔM|/M(y) がどちらも 2% 以下になったら「一致」と表示する（値は提案で、知覚実験に基づく根拠はない）。
