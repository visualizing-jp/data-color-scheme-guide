## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。講義スライド「データの性質を表現する色の考え方」をもとに、「色相は種類の違いを、明るさ（明度）は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人です。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 を同梱）で、図を担当ごとに、互いのファイルに触れずに並行して作っています。最初に `README.md` を読んでください。図の契約、担当範囲、共通の操作部品、動かし方、撮影と表示検査（`npm run shots`）が書いてあります。図に渡される `deps`（`d3`、`color`、`palettes`、`prefectures`、`tilemap`）の各関数の意味は、`lib/color.js`・`lib/palettes.js`・`lib/tilemap.js` の JSDoc と、`data/prefectures.json` の `meta` を読んでください。これらは実装済みです。図のひな形は `widgets/_template/`、実装済みの図の例は `widgets/quiz/` です。

あなたの作業ブランチは `w2/wd-scheme-anatomy`（`w2/base` から分岐）です。

## 用語と表記（ページ全体で統一）
- スキーム名は「定性的」「連続的」「分岐的」。この順で並べます。
- 見た目の明るさは「明度」（OKLab の L。図の表示では 0〜100%）。鮮やかさは「彩度」。色の種類は「色相」。
- 色覚のタイプは「通常」「P型」「D型」「T型」（操作部品のラベル）。
- 文体は、です・ます体。数字と単位は半角で、間を空けません（39.5%、580nm）。
- 図の中の文言は日本語だけにします（略語とパレット名を除く）。

## 仕事
第3章「データの性質とカラースキーム」の図 `widgets/scheme-anatomy/` を作ります。3種類のカラースキームが、明度の並び方の点でどう違うかを、読者がパレットを切り替えながら確かめる図です。伝えたいことは「定性的スキームは色相の違いで区別し、明度は一方向には並ばない。連続的スキームは明度が一方向に変わる。分岐的スキームは中央が最も明るく、両端に向かって暗くなる」です。

### 図の構成
- 見出し「スキームの中身を、明度で見る」。
- 操作部品：「スキーム」の選択（定性的／連続的／分岐的）、「パレット」の選択（`palettes.list(type)` の `label`。`<select>` を使います。初期値は `palettes.DEFAULTS` の各種別のパレット）、「色の数」スライダー（そのパレットの `classCounts` の範囲。初期値は定性的 8、連続的 7、分岐的 7。範囲に収まらないときは収まる値）、切り替え「グレースケールにする」。
- 色見本の帯：`palettes.get(id, n)` の n 色を横に並べます。「グレースケールにする」を入れると `color.toGray` の色になります。
- 明度の折れ線グラフ：横軸は色の並び順（帯の各色の真下に点が来るようにそろえる）、縦軸は明度（0〜100%、`color.lightness`）。各点はその色で塗った丸（細い濃いグレーの縁つき）、点の間をグレーの線で結びます。縦軸に 0%・50%・100% の目盛り。
- 形の説明（`aria-live="polite"`）：実際の値から判定して文を出します。
  - 連続的で、明度が一方向に変わっているとき：「明度が一方向に変わっています。明るさの順が、そのまま値の大小の順になります。」
  - 分岐的で、中央付近が最も明るく両端が暗いとき：「中央がいちばん明るく、両端に向かって暗くなっています。中央が基準点、両端が『大きく増えた』『大きく減った』を表します。」
  - 定性的のとき：「明度は上がったり下がったりで、一方向には並んでいません。色相の違いで区別するスキームです。」
  - 種別と形が合わない場合（一部のパレットや色の数で起こりえます）は、実際の形をそのまま述べる文にします（例：「このパレットは、この色の数では明度の差が小さくなっています。」）。
- 色覚への配慮の表示：`palettes.isColorblindSafe(id, n)` が真なら「この色の数では、色覚のタイプが違っても見分けやすいとされています」、偽なら「この色の数では、見分けにくい色の組が含まれます」。出典として「ColorBrewer の判定」と添えます（Okabe–Ito のときは「色覚に配慮して作られたパレットです」）。
- 図の下の注（`.fig-note`）：「パレットは ColorBrewer と Okabe–Ito によります。明度は OKLab の L です。」

### 確かめる動作
- 3種別の初期パレットで、形の説明がそれぞれ上の3つの文になる。
- スキームを切り替えると、パレットの選択肢と色の数の範囲が変わる。色の数を動かすと、帯とグラフの点の数が変わる。
- 連続的の全18パレット・全階級数で、明度が一方向かどうかを実際に計算し、一方向でない組があれば、パレット名と階級数を報告に書く（図はそのまま正直に表示する）。分岐的の全9パレットについても、中央が最も明るいかを同じように確かめて報告に書く。
- 「グレースケールにする」で、連続的の帯は濃淡の順が残り、定性的の帯は似たグレーが並ぶ。
- 幅390pxで、帯の各色とグラフの点の位置がそろっている。

## 表示の決まり
README の「図の契約」に従います。特に：SVG には `viewBox` を付ける。幅390pxでも図の中の文字が 11px 以上で表示される。操作部品は `css/base.css` の共通クラスを使い、キーボードで操作できる。ページのUIは無彩色に保ち、色が出るのは図の中の色見本・地図・グラフだけにする。判定（`.verdict`）は記号だけに頼らず、判定の語を文字として含める。操作の結果を文で伝える箇所は `aria-live="polite"` にする。
