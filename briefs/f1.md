## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。「色相は種類の違いを、明度は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人で、スマホで読む人も多いです。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 同梱）です。骨組み、共有モジュール、9つの図、本文がそろい、いまチェックアウトされている `w3/base` に全部が統合されています。この状態を、3人の査読担当（コード全体のレビュー、科学的な正確さの査読、初学者としての通読）が確認しました。あなたの仕事は、その指摘のうち、下に挙げたものを直すことです。同時に、ほかの3人の担当が、別のファイルを直しています。

最初に `README.md` を読んでください（図の契約、共通の操作部品、撮影と表示検査 `npm run shots`）。作業ブランチは `w3/f1-tilemap-maps`（`w3/base` から分岐）です。

## 直す内容

### A. タイル地図の操作を共通化する（`lib/tilemap.js`、`tests/tilemap.test.js`）
いまは、地図のマスに触れたときの表示とキーボード操作を、図ごとに別々に作っていて、動きが食い違っています（矢印キーの移動先の選び方、フォーカスの枠の出方）。これを `lib/tilemap.js` にまとめます。
1. `render` のオプションに `onActive` を加えます：`onActive(pref | null)`。マスにポインタが乗ったとき、タップしたとき、キーボードのフォーカスが移ったときに、その都道府県のオブジェクトで呼ばれ、地図から離れたときに `null` で呼ばれます。`onActive` を渡したときだけ、次の操作が有効になります。
2. キーボード操作：Tab では地図に1回だけ止まり（最初に止まるマスは、`initialCode` オプションで指定。省略時は北海道 `'01'`）、矢印キーでその方向のいちばん近いマスへ移ります（まっすぐその方向にあるマスを優先し、なければ斜めのうち近いもの）。フォーカスの枠は、`:focus-visible` のときだけ出します。
3. `<svg>` 要素そのものには Tab で止まらないようにします（`tabindex="-1"`）。いまは、マスより先に `<svg>` にフォーカスが止まります。
4. マスに印を付ける関数を、戻り値に加えます：`mark(codes)`。渡した都道府県コードのマスに、濃いグレーの太い枠と内側の白い線を付けます（濃い色のマスでも見えるように）。空の配列で消えます。
5. JSDoc と README の記述（README は別の担当が編集するので、報告に、README に書くべき文面を添えてください）。移動先を決める関数は、テストできる形に切り出して検査します。

### B. 導入図（`widgets/intro-compare/`）
- 地図の操作と、答えの印を、A の `onActive` と `mark` に置き換えます。Tab で地図に入ったとき、最初に止まるのは北海道にします（いまは、最初に秋田県に止まり、「秋田県 39.5%」と表示されて、問いの答えがわかってしまいます）。
- ボタンを `.ctl-button`（「答えを見る」は `.ctl-button--primary`）に。
- 図の注に、「総務省統計局『人口推計』をもとに加工して作成」の趣旨を入れます。
- 幅390pxでは県名がマスに出ないので、「答えを見る」のあと、印を付けたマスのそばに県名を表示します（秋田県・東京都の2つだけ。地図に重ねたラベルで、文字は 11px 以上）。幅1280pxでも同じように出します。

### C. データ×スキーム対応表（`widgets/scheme-matrix/`）
- 見出しを「データ×スキーム対応表：組み合わせを試す」に。
- 地図の操作を、A の `onActive` に置き換えます。
- `verdicts.json` の `aged65` × `sequential` の `reason` を、実際の塗りに合わせて差し替えます（最も濃い階級に入るのは秋田と高知だけです）：
  「秋田・高知がいちばん濃く、青森・山形などがその次に濃い色、東京・沖縄・愛知のあたりが淡い色になり、色の濃さの順に割合の高低を読み取れます。量の大小を明るさで伝える基本の形です。」
- 幅の狭い画面では、選んだ組み合わせの判定と理由が、地図の下に隠れて、押すたびにスクロールが要ります。幅の狭い画面では、並びを「操作部品 → 9通りの一覧 → 判定と理由 → 地図 → 凡例」の順にします。
- `popChange` × `diverging` のとき、青の側の色になる県が東京都だけで、1マスしかないため、スマホでは名前がわかりません。この組み合わせのときは、東京都のマスのそばに「東京」のラベルを出します（B と同じ、地図に重ねたラベル）。同じように、`aged65` × `sequential` のときは、最も濃い「秋田」と最も淡い「東京」にラベルを出します。
- 図の注に、「総務省統計局『人口推計』をもとに加工して作成」の趣旨を入れます。
- 理由文の `aria-live` は、組み合わせが変わったときだけ書き換えます。
