## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。講義スライド「データの性質を表現する色の考え方」をもとに、「色相は種類の違いを、明るさ（明度）は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人です。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 を同梱）で、図・共有モジュール・本文を、担当ごとに互いのファイルに触れずに並行して作っています。最初に `README.md` を読んでください。図の契約、担当範囲、共通の操作部品、動かし方が書いてあります。

あなたの作業ブランチは `w1/q1-screenshots`（`s0/skeleton` から分岐）です。

## 仕事
レビュー担当と検証担当が1コマンドで使える、撮影と表示検査のスクリプト `scripts/shots.mjs` を作り、`package.json` に `"shots": "node scripts/shots.mjs"` を加えます。

- 静的ファイルサーバ（`scripts/serve.mjs` の仕組みを再利用）を空いているポートで自分で起動し、終わったら止めます。
- 対象ページ：`index.html` と、リポジトリ内のすべての `demo.html`（`widgets/*/demo.html`、`lib/*.demo.html`）。引数でパスを渡したときは、そのページだけを対象にします（例：`npm run shots -- widgets/quiz/demo.html`）。
- 各ページを幅1280pxと幅390pxで開き、`<html data-widgets-ready="true">` が付くのを待ってから、ページ全体のスクリーンショットを `screenshots/<ページ名>-<幅>.png` に保存します（`screenshots/` は `.gitignore` に加えます）。`index.html` では、各図（`[data-widget]`）を要素単位でも撮影します。
- 各ページ・各幅で次を検査し、結果を表にして標準出力に出します：コンソールのエラーと失敗したリクエストの件数（0件であること）、横スクロールがないこと（`scrollWidth <= innerWidth`）、「図を表示できませんでした」のエラー表示がないこと、SVG内の文字（`text` 要素）の表示上の最小サイズ（11px 以上であること）、準備中のプレースホルダの個数（これは件数の表示だけで、不合格にはしません）。
- 1つでも不合格があれば、終了コードを 0 以外にします。
- Playwright はこの環境に導入済みで、`require('playwright')` がどのディレクトリからでも使え、`chromium.launch()` はオプション不要です。`package.json` の依存には加えず、ESモジュールから `createRequire(import.meta.url)` で読み込みます。読み込めない環境では、その旨のメッセージを出して終了します。
- README に「撮影と表示検査」の節を加え、使い方と検査項目を書きます。

## 完了条件
1. `npm test` がすべて通る。
2. `npm run shots` が、現在のリポジトリ（図はまだ準備中の状態）で合格し、`screenshots/` に画像が保存される。
3. 一時的に、コンソールエラーを出すページ、横スクロールが出るページ、SVGの文字が小さすぎるページを作って、それぞれ不合格になり終了コードが 0 以外になることを確かめる（確認用のページはコミットしない）。

## Git とプルリクエスト
- 日本語のコミットメッセージでコミットし、ブランチ `w1/q1-screenshots` に push します。確認用のスクリプトやスクリーンショットはコミットに含めません。
- push 後、`main` 向けの Draft のプルリクエストを作ります（`s0/skeleton` が `main` にマージされるまでは、差分に骨組みの分も表示されます）。
  `gh api repos/visualizing-jp/data-color-scheme-guide/pulls -f title='Q1: スクリーンショット撮影と表示検査のスクリプト' -f head='w1/q1-screenshots' -f base='main' -F draft=true -F body=@本文ファイル`
- プルリクエストの本文は日本語で、概要、変更内容、確認結果（テスト済み／実機確認済みを区別し、測った数値を書く）を書きます。
