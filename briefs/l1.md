## 1. sRGB 伝達関数【確認済】

出典：CSS Color Module Level 4（W3C Candidate Recommendation Draft, 18 November 2026、This version: https://www.w3.org/TR/2026/CRD-css-color-4-20261118/ ）
- 定義：https://www.w3.org/TR/css-color-4/#predefined-sRGB
- サンプルコード：https://www.w3.org/TR/css-color-4/#color-conversion-code（`lin_sRGB`／`gam_sRGB`）

デコード（ガンマ補正済み → 線形、`srgbToLinear`）。`c` はガンマ補正済みの値、`cl` は線形光の値：
```
if (|c| <= 0.04045)  cl = c / 12.92
else                 cl = sign(c) * ((|c| + 0.055) / 1.055) ^ 2.4
```
エンコード（線形 → ガンマ補正済み、`linearToSrgb`）：
```
if (|cl| > 0.0031308) c = sign(cl) * (1.055 * |cl| ^ (1/2.4) - 0.055)
else                  c = 12.92 * cl
```
仕様のコードは負の値も符号を反転して扱う「拡張」版です。仕様コード中の該当部分（原文）：
```js
function lin_sRGB(RGB) {
	return RGB.map(function (val) {
		let sign = val < 0? -1 : 1;
		let abs = Math.abs(val);
		if (abs <= 0.04045) {
			return val / 12.92;
		}
		return sign * (Math.pow((abs + 0.055) / 1.055, 2.4));
	});
}
function gam_sRGB(RGB) {
	return RGB.map(function (val) {
		let sign = val < 0? -1 : 1;
		let abs = Math.abs(val);
		if (abs > 0.0031308) {
			return sign * (1.055 * Math.pow(abs, 1/2.4) - 0.055);
		}
		return 12.92 * val;
	});
}
```
（コメント行は省略しています。）この式が colour-science 0.4.6 の `eotf_sRGB`／`eotf_inverse_sRGB` と 0〜1 の1001点で完全に一致することを確かめました（差 0.0）。

## 2. OKLab 変換係数【確認済】

出典：Björn Ottosson, "A perceptual color space for image processing"（公開 2020-12-23、dateModified 2021-01-27）https://bottosson.github.io/posts/oklab/
原文の注記："The matrices were updated 2021-01-25. The new matrices have been derived using a higher precision sRGB matrix and with exactly matching D65 values."

### 2.1 線形sRGB → OKLab（原文のC++をそのまま転記）
```cpp
float l = 0.4122214708f * c.r + 0.5363325363f * c.g + 0.0514459929f * c.b;
float m = 0.2119034982f * c.r + 0.6806995451f * c.g + 0.1073969566f * c.b;
float s = 0.0883024619f * c.r + 0.2817188376f * c.g + 0.6299787005f * c.b;
float l_ = cbrtf(l);
float m_ = cbrtf(m);
float s_ = cbrtf(s);
return {
    0.2104542553f*l_ + 0.7936177850f*m_ - 0.0040720468f*s_,
    1.9779984951f*l_ - 2.4285922050f*m_ + 0.4505937099f*s_,
    0.0259040371f*l_ + 0.7827717662f*m_ - 0.8086757660f*s_,
};
```
### 2.2 OKLab → 線形sRGB（原文のC++をそのまま転記）
```cpp
float l_ = c.L + 0.3963377774f * c.a + 0.2158037573f * c.b;
float m_ = c.L - 0.1055613458f * c.a - 0.0638541728f * c.b;
float s_ = c.L - 0.0894841775f * c.a - 1.2914855480f * c.b;
float l = l_*l_*l_;
float m = m_*m_*m_;
float s = s_*s_*s_;
return {
    +4.0767416621f * l - 3.3077115913f * m + 0.2309699292f * s,
    -1.2684380046f * l + 2.6097574011f * m - 0.3413193965f * s,
    -0.0041960863f * l - 0.7034186147f * m + 1.7076147010f * s,
};
```
- JSでは `Math.cbrt` を使います（負の入力も正しく扱えます）。`f` サフィックスは外し、計算は倍精度で行います。
- LCh：`C = sqrt(a²+b²)`、`h = atan2(b, a)`（度に直して 0〜360 に正規化）。逆は `a = C·cos h`、`b = C·sin h`（原記事より）。
- 自分で行った検証【確認済】：
  - 原記事の XYZ→OKLab の例の表（4組、小数第3位で丸めたもの）を、記事の M1・M2 の XYZ 経路で再計算したところ、4組すべて一致しました。
  - colour-science 0.4.6 の `XYZ_to_Oklab(sRGB_to_XYZ(rgb))` とは最大 1.1e-4 ずれます。colour-science は独自の sRGB→XYZ 行列と白色点の値を使うためで、正常な範囲です。テストは本書の値（Ottosson の線形sRGB係数を直接使った値）を正としてください。
- CSS Color 4 の `XYZ_to_OKLab` には M1 をさらに高精度にした値（0.8190224379967030 …）があります。今回は Ottosson の線形sRGB係数を使うので関係ありません。

### 2.3 `oklchToHex` の色域外処理
仕様に「l と h を保ったまま c を下げる」とあるので、c について二分探索します（参照実装では60回反復し、色域内の判定は線形RGBの各成分が `[-1e-7, 1+1e-7]` に入ること）。最後に [0,1] にクリップしてエンコードします。
- **注意**：sRGBの原色（`#ff0000` など）を往復させると、浮動小数の誤差で線形値が `1.0000000002` や `-1e-10` になります。判定に ε を入れないと、色域外と誤判定して c を下げる処理に入ってしまいます。ε を 1e-7 程度にしてください。
- 参考【確認済】：CSS Color 4 の標準的な色域マッピングは "Binary Search Gamut Mapping with Local MINDE"（https://www.w3.org/TR/css-color-4/#css-gamut-mapping 、JND 0.02 で切り取りと組み合わせる方式）です。今回の確定仕様は単純に c を下げるだけなので、CSSの結果とは少し違うことがあります。

### 3.1 行列を掛ける色空間：線形RGBか、ガンマ補正済みか

**結論：線形RGBに掛ける**（`hex → srgbToLinear → M·rgb → clip[0,1] → linearToSrgb → hex`）。
ただし、**論文本文に「線形RGBに掛ける」と明記した文はありません**。根拠と反対材料を分けて書きます。

**(a) 論文本文（PDFから引用、【確認済】）— 理論上は線形RGBが前提**
- 4.1節、Eq. 8 の直前：
  > "We obtain a transformation from an RGB color space to an opponent-color space simply by projecting the spectral power distributions ϕR (λ ), ϕG (λ ), and ϕB (λ ) of the RGB primaries onto the set of basis functions W S(λ ), Y B(λ ), and RG(λ ) that define the opponent-color space, as shown in Eq. 8."

  行列は、RGB原色の**分光放射分布を積分**して作られています。RGB値を原色の光の量（重み）とみなす線形モデルなので、成り立つのは線形光のRGBのときだけです（ここは本文からの推論です）。
- Eq. 9 の説明：
  > "They guarantee that the achromatic colors (gray shades) have the exact same coordinates ranging from (0, 0, 0) to (1, 1, 1) both in RGB as well as in all possible versions of the opponent-color spaces"

  行の和が1になるのはこのためです。灰色が変わらない性質は、どちらの空間で掛けても成り立ちます。
- Eq. 11：`[Rs, Gs, Bs]ᵀ = Γnormal⁻¹ Γ [R, G, B]ᵀ`。ガンマについての記述はありません。
- 5.1節（実験条件、ガンマが出てくる唯一の箇所）：
  > "The monitors were calibrated using a ColorVision Spyder 2 colorimeter (Gamma 2.2 and White Point 6500K)."

  被験者実験のモニタ設定の話で、行列を掛ける空間については何も言っていません。
- 本文を `gamma|linear|sRGB|calibrat|interpol|clamp|clip|gamut` で全文検索しましたが、適用する空間を述べた箇所はありませんでした。

**(b) 行列ページ（【WebFetch経由】）**："The RGB vector on the right represents the reference RGB color, which is multiplied by the matrix" とあるだけで、線形かガンマかは書かれていません。

### 3.2 重症度の補間
- 行列ページ【WebFetch経由】："The matrices in Table 1 were computed for severities growing with a step of 0.1." と "it is also possible to interpolate between the two matrices with nearest severities."（著者自身が近い2つの行列の補間を認めています。補間の方式は書かれていませんが、文脈から線形補間と解釈しました。）
- 論文の重症度は錐体の分光感度のずれ（nm）です【確認済：PDF】："A shift of approximately 20 nm represents a severe case of protanomaly or deuteranomaly"。表の重症度 1.0 は、P/D ではおおむね 2色覚（protanope／deuteranope）に相当します。行列はずれ量に対して非線形なので、0.1 の間を線形補間するのは近似ですが、成分は滑らかに変わるので実用上は問題ありません。
- tritan について【確認済：colour-science の警告文】："The pre-generated matrices are using a shift value in domain [5, 59] contrary to the domain [0, 20] used for protanomaly and deuteranomaly simulation."。論文【確認済：PDF】は "our model is not intended to handle tritanopia" と書いています。**tritan の 1.0 は「3型2色覚」の正確なシミュレーションではない**と、ページで一言断っておくのが誠実です。
- 推奨する式（JS）：
  ```js
  const x = clamp(severity, 0, 1) * 10;
  const k = Math.min(Math.floor(x), 9);   // 1.0 のときは k=9, f=1 → 行列[10]
  const f = x - k;
  M = (1 - f) * T[k] + f * T[k + 1];      // 成分ごと
  ```
- **既存ライブラリの補間には不具合があり、テストの正解値に使えません**【確認済】：
  - colour-science 0.4.6 の `matrix_cvd_Machado2009`：`np.searchsorted` の結果を下側の添字として使っているので、格子点の間では上側の区間から**外挿**になります。例：protan 0.15 の1行目は `[0.786988, 0.269488, -0.056474]` を返します（0.2 と 0.3 から外挿した値）。正しい線形補間は `[0.795467, 0.258455, -0.053921]` です。この誤った値は同ライブラリの docstring の例にもそのまま載っています。
  - DaltonLens-Python の `Simulator_Machado2009`：`alpha = severity - severity_lower/10.0` となっていて10倍が抜けているため、alpha が 0〜0.1 にしかなりません。
  - 格子点（0.0, 0.1, …, 1.0）では、どちらも正しい行列を返します（colour-science で33点が一致することを確認）。

### 3.3 0〜1 を外れた値
- 論文と行列ページには記述がありません【確認済：PDF全文を検索】。
- 行の和は1（誤差は丸めの ±1e-6 以内、33行列すべてで確認）なので、白・黒・灰色は変わりません。一方、原色を入れると負の値や1を超える値が普通に出ます（例：`#0000ff`・protan・1.0 → 線形 `[-0.204868, 0.099216, 1.051998]`）。
- 推奨：**線形RGBの段階で [0,1] にクリップしてからガンマ補正**します。DaltonLens と同じ方式で、Filter Effects の "The RGBA result from each filter primitive will be clamped into the allowable ranges for colors and opacity values."（フィルタの結果は許される範囲に収められる）とも同じ振る舞いです【確認済】。sRGBの拡張伝達関数は負の値も扱えますが、色域外の値をそのまま `#rrggbb` に丸めると成分ごとにばらばらに切られることになり、結果は同じです。切り取る位置は線形の段階に統一してください。

## 5. 初学者向けに OKLab の L を説明するときの注意

**一言で**：「OKLab の L も CIELAB の L* も“見た目の明るさ”を近似した尺度です。目盛りが違い（L は 0〜1、L* は 0〜100）、色によってはどちらが明るいかの判定まで食い違います。」

数値の例（自分で計算、L* は colour-science の D65）：
| 色 | 輝度 Y | CIELAB L* | OKLab L |
|---|---|---|---|
| `#808080` | 0.2159 | 53.59 | 0.5999 |
| `#ff0000` | 0.2126 | 53.23 | 0.6280 |
| `#0000ff` | 0.0722 | 32.30 | 0.4520 |
| `#00ff00` | 0.7152 | 87.74 | 0.8664 |
| `#ffff00` | 0.9278 | 97.14 | 0.9680 |

- 純赤は、L* では中間グレーより**わずかに暗い**のに、OKLab では**明らか**に明るい側になります。CIELAB の L* は輝度 Y だけで決まりますが、OKLab の L は錐体応答（LMS）から作られるため、彩度の高い色をやや明るく見積もります。L* の値を 100 で割っても OKLab の L にはなりません（灰色 `#808080`：53.6 と 0.600）。
- L は輝度（Y）でも、WCAG のコントラスト比でもありません。文字のコントラスト判定には使わないこと、と添えると誤解を防げます。
- Ottosson によれば、OKLab は「通常の明るい環境で見る」前提で、CAM16 で作った模擬データに合わせて作られました【確認済：原記事 "Should assume normal well lit viewing conditions"、"Since the lightness and chroma data was generated using CAM16 rather than being data from experiments, this data can't be used to say which model best matches human perception."】。L はあくまで良い近似であり、知覚そのものではない、という言い方が正確です。
