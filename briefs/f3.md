## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。「色相は種類の違いを、明度は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人で、スマホで読む人も多いです。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 同梱）です。骨組み、共有モジュール、9つの図、本文がそろい、いまチェックアウトされている `w3/base` に全部が統合されています。この状態を、3人の査読担当（コード全体のレビュー、科学的な正確さの査読、初学者としての通読）が確認しました。あなたの仕事は、その指摘のうち、下に挙げたものを直すことです。同時に、ほかの3人の担当が、別のファイルを直しています。

最初に `README.md` を読んでください（図の契約、共通の操作部品、撮影と表示検査 `npm run shots`）。作業ブランチは `w3/f3-widgets`（`w3/base` から分岐）です。

## 直す内容

### A. 錐体エクスプローラ（`widgets/cone-explorer/`）
1. 見出しを「錐体エクスプローラ：波長を動かして、3種類の錐体の反応を見る」に（`p.fig-title`）。後半の「ちがう光でも、同じ色に見える」は、図の中の小見出し `p.fig-subtitle` にします（いまは、この図だけ `h3` が2つあります）。
2. 感度が最大になる波長のラベルを、「S 445nm付近」「M 545nm付近」「L 570nm付近」に（データが5nm刻みのためです）。
3. 図の注の「2°錐体分光感度」を「2°視野の錐体分光感度」に。
4. ボタンを `.ctl-button`（「ぴったり合わせる」は `.ctl-button--primary`）に。
5. 単色光の近似表示の色を、図の中で自前で計算しています（XYZ から sRGB への変換）。計算はそのままで構いません。なぜ `lib/color.js` を使わずに計算しているのか（単色光は sRGB の色域の外にあり、近似の方法がこの図に固有のため）を、コードのコメントに書きます。

### B. 色の3つのつまみ（`widgets/three-knobs/`）
1. 見出しを「色の3つのつまみ：色相・彩度・明度で色を作る」に。
2. 「彩度の上限」の説明を、「画面で表示できる彩度の上限」に。
3. 「色相だけを変えた12色」の帯で、その色相では出せない彩度のために、自動で彩度が下がっている色があります（たとえば明度60%・彩度0.12 のとき、色相 180° と 210°）。帯の下の一言に、「画面で表示できない色相は、彩度を下げて表示しています。」を、該当する色があるときだけ添えます。
4. 明度を 100%（または 0%）にすると、彩度が 0 に固定され、12色がすべて白（または黒）になります。このとき、帯の下に「明度が100%（0%）では、どの色相も白（黒）になります。」と表示します。
5. 色相を帯の形に並べていることがわかるように、色相の帯の見出しを「色相だけを変えた12色（色相環を帯に伸ばしたもの）」にします。
6. `aria-live` は、「グレースケールにする」を切り替えたときだけ書き換えます。

### C. スキーム解剖（`widgets/scheme-anatomy/`）
1. 見出しを「スキーム解剖：スキームの中身を、明度で見る」に。
2. 形の説明の `aria-live` は、文が変わったときだけ書き換えます。
3. 色覚への配慮の表示で「見分けにくい色の組が含まれます」と出すとき、判定の段階（`.verdict` の修飾クラス）は「条件つき」のままにし、文を「この色の数では、色覚のタイプによって見分けにくい組が含まれるとされています（ColorBrewer の判定）」にします。

### D. 判断フロー（`widgets/decision-flow/`）
1. 見出しを「判断フロー：データを見て、スキームを選ぶ」に。
2. 定性的スキームの例を「性別、地方区分、業種」に（47都道府県は、色だけでは区別できないためです）。分岐的スキームの例を「人口の増減率、前年との差、平均との差」に。
3. 定性的スキームの説明に、一言加えます：「色で区別できるのは、8色程度までです。」
4. ボタンを `.ctl-button` に。

### E. 理解度クイズ（`widgets/quiz/`）
1. 見出しは「理解度クイズ：このデータに合うスキームは？」（いまのままなら変更なし）。
2. `questions.json` の q2（映画レビューの星の数）の、`whyNot.diverging` を差し替えます：「平均の高低だけを見たいなら、基準点は要りません。『星3つより上か下か』を見せたいときは、分岐的スキームも使えます。」
3. ボタンを `.ctl-button`（「次の問題へ」「結果を見る」は `.ctl-button--primary`）に。選択肢のボタンは、いまの専用スタイルのままで構いません。
