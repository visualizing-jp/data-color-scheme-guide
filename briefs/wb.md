## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。講義スライド「データの性質を表現する色の考え方」をもとに、「色相は種類の違いを、明るさ（明度）は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人です。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 を同梱）で、図を担当ごとに、互いのファイルに触れずに並行して作っています。最初に `README.md` を読んでください。図の契約、担当範囲、共通の操作部品、動かし方、撮影と表示検査（`npm run shots`）が書いてあります。図に渡される `deps`（`d3`、`color`、`palettes`、`prefectures`、`tilemap`）の各関数の意味は、`lib/color.js`・`lib/palettes.js`・`lib/tilemap.js` の JSDoc と、`data/prefectures.json` の `meta` を読んでください。これらは実装済みです。図のひな形は `widgets/_template/`、実装済みの図の例は `widgets/quiz/` です。

あなたの作業ブランチは `w2/wb-three-knobs`（`w2/base` から分岐）です。

## 仕事
第2章「色の3つのつまみ」の図 `widgets/three-knobs/` を作ります。読者に伝えたいことは次の2つで、これが次の章（データの性質に色を対応させる）の土台になります。
1. 色は、色相・彩度・明度の3つで説明できる。
2. 色相には順序がなく、明度には順序がある。グレースケールにすると、色相と彩度は消えて、明度だけが残る。

### 図の構成（上から順に）
- 見出し「3つのつまみで色を作る」。
- 操作部品：「色相」スライダー（0〜360°、初期値 250°）、「彩度」スライダー（0〜その明度と色相で出せる最大値。`color.maxChroma(l, h)` で上限を求め、明度や色相を動かして上限が下がったら値も上限に合わせる。初期値 0.12）、「明度」スライダー（0〜100%、初期値 60%）、切り替え「グレースケールにする」。色は `color.oklchToHex` で求めます。
- 大きな色見本と、その色の `#rrggbb`、色相・彩度・明度の値。
- 「色相だけを変えた12色」の帯：いまの明度と彩度のまま、色相を30°ずつ変えた12色（出せない彩度は自動で下がります）。帯の下に一言「明度は同じ。どれが上、という順序はありません。」
- 「明度だけを変えた7色」の帯：いまの色相と彩度のまま、明度を 95%・82%・69%・56%・43%・30%・17% にした7色。帯の下に一言「明るい色から暗い色へ、順に並びます。」
- 「グレースケールにする」を入れると、大きな色見本と2本の帯が `color.toGray` の色に変わります。色相の帯は12色がほぼ同じグレーになり、明度の帯は7段階のグレーのまま順序が残ります。切り替えたときの一言（`aria-live`）：「色相と彩度が消えて、明度だけが残りました。色相の帯は見分けられなくなり、明度の帯は順序が残っています。」
- 補足の枠「パソコンの色選択にあるHSBの『明るさ』とのちがい」：黄色 `#ffff00` と青 `#0000ff` を並べ、それぞれに「HSBの明るさ（B）100%」と、`color.lightness` で求めた明度（%）を表示します。グレースケールの切り替えは、この2色にも効きます。一言「HSBでは同じ『明るさ100%』でも、見た目の明るさ（明度）は大きく違います。この図は、見た目の明るさに近いOKLCHという方式で計算しています。」

### 確かめる動作
- 3つのスライダーを動かすと、色見本・値・2本の帯が変わる。彩度の上限が明度と色相に応じて変わり、値が上限を超えない。
- 「グレースケールにする」を入れると、色相の帯の12色の明度の差（最大と最小の差）が 3% 以下になり、明度の帯の7色は順に暗くなる（`color.lightness` で測る）。
- 黄色と青の明度の表示が、それぞれ約 97% と約 45% になる。
