## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。「色相は種類の違いを、明度は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人で、スマホで読む人も多いです。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 同梱）です。骨組み、共有モジュール、9つの図、本文がそろい、いまチェックアウトされている `w3/base` に全部が統合されています。この状態を、3人の査読担当（コード全体のレビュー、科学的な正確さの査読、初学者としての通読）が確認しました。あなたの仕事は、その指摘のうち、下に挙げたものを直すことです。同時に、ほかの3人の担当が、別のファイルを直しています。

最初に `README.md` を読んでください（図の契約、共通の操作部品、撮影と表示検査 `npm run shots`）。作業ブランチは `w3/f2-cvd-pairs`（`w3/base` から分岐）です。

## 直す内容

### A. 色覚シミュレータ（`widgets/cvd-simulator/`）
1. 見出しを「色覚シミュレータ：見え方のちがいを確かめる」に。
2. 区画の順番を変えます。本文は、まず地方区分の地図で、隣り合う地方の色が近づくところを探すよう案内しています。いまは地図が図のいちばん下にあり、幅390pxでは、操作部品から地図まで約1000pxスクロールが要ります。並びを「操作部品 → 地方区分のタイル地図（もとの色／シミュレーション後の色）→ 3種類のカラースキーム → 色相環 → まとめの文」の順にします。
3. 幅の狭い画面で、図を下へスクロールしても「見え方」の選択が使えるように、操作部品の行を、図の中で画面の上端に貼り付く形（`position: sticky`）にします。貼り付いたときに、下の内容が透けて読みにくくならないよう、背景と下端の線を付けます。
4. 「見え方」の選択肢に、どの錐体に関わるかを添えます：「P型（L錐体）」「D型（M錐体）」「T型（S錐体）」。幅の狭い画面で折り返しても読めるようにします。
5. 「見分けにくい組」の表示：いまは「1番目と4番目の色」のように番号で出ますが、色見本に番号がありません。帯の各色の下に小さく番号（1、2、3…）を付け、見分けにくい組は、該当する2色の小さな色見本を並べたうえで番号を添えます。
6. 地図は、マスに触れる・タップする・キーボードで移動すると、地方名と県名が地図の下に出るようにします（もとの色の地図と、シミュレーション後の色の地図の両方）。この操作は、`lib/tilemap.js` の `render` に新しく加わる `onActive` オプションを使います。別の担当が同時に実装していて、仕様は次のとおりです：`render(el, { …, onActive(pref | null) })`。マスにポインタが乗ったとき、タップしたとき、キーボードのフォーカスが移ったときに、その都道府県のオブジェクトで呼ばれ、地図から離れたときに `null` で呼ばれる。Tab では地図に1回だけ止まり、矢印キーで隣のマスへ移る。あなたのブランチの `lib/tilemap.js` にはまだこの機能がないので、`onActive` を渡す実装だけを書き、動作の確認は、マスの `data-code` 属性を使った確認用のスクリプトで代えてください（`lib/tilemap.js` は編集しません）。統合後に、私が動作を確かめます。
7. 図の注に、次を加えます：「T型の再現は、もとの方法が想定していない部分を含むため、特に粗い近似です。」「『見分けにくい組』の基準は、このページで決めた目安です。」
8. まとめの文の `aria-live` は、文が変わったときだけ書き換え、強さのスライダーは、止まってから書き換えます。

### B. 見分けにくい色の組（`widgets/problem-pairs/`）
1. 見出しを「見分けにくい色の組：明度の差をつける」に。
2. 判定の目安を、色覚シミュレータと同じ 0.06 にそろえます：2色の差が 0.06 未満「見分けにくい」、0.06 以上 0.12 未満「やや見分けにくい」、0.12 以上「見分けやすい」。
3. 「差」という語が2つの意味で出てきて混乱します（スライダーの「明度の差 0%」と、数値の「差 0.32」）。数値のほうは「色の差」と呼び、スライダーは「明度の差」のままにします。図の中の文言を、この2語で統一します。
4. 「色の差」の横棒に、目安の位置（0.06 と 0.12）を示す細い線を入れ、どこまで広げれば「見分けやすい」になるかがわかるようにします。
5. 本文は「これらの色のいずれかを、同じ明度のグレーの上に置いた場合も、見分けにくくなります」と書いていますが、図で確かめる手段がありません。切り替え「片方を同じ明度のグレーにする」を加えます。入れると、色Bが、色Aと同じ明度のグレー（`color.toGray` で求める）に置き換わり、ほかの表示（見え方ごとの色の差、判定、明度の差のスライダー）はそのまま働きます。
6. 「見え方」の選択肢を、色覚シミュレータと同じ「P型（L錐体）」「D型（M錐体）」「T型（S錐体）」に。
7. ボタンを `.ctl-button` に。
8. 図の注に、「『見分けにくい』の基準は、このページで決めた目安です。」と、「T型の再現は、特に粗い近似です。」を加えます。
9. 数値と判定の `aria-live` は、スライダーが止まってから書き換えます。
10. 直したあと、4組それぞれについて、明度の差 0% のときの、通常・P型・D型・T型での色の差と判定を表にして、報告に書いてください（本文は「赤と緑・オレンジと緑は主にP型・D型で、黄色とピンク・青と緑は主にT型で差が小さくなる」と書きます。図の表示がこれと合っているかを確かめるためです）。
