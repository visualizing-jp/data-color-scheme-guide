## 背景
リポジトリ visualizing-jp/data-color-scheme-guide は、初学者向けの日本語スクロール型解説ページ「データの性質に合ったカラースキームの選び方」です。講義スライド「データの性質を表現する色の考え方」をもとに、「色相は種類の違いを、明るさ（明度）は量の大小を伝える」という一本の筋で、色が見えるしくみ → 色の3つのつまみ → データの性質とカラースキーム（定性的・連続的・分岐的）→ 色覚の多様性への配慮 → まとめ、の順に説明します。読者は、色彩やデータ可視化を学び始めたばかりの学生・社会人です。

ビルド工程のない静的サイト（バニラJSのESモジュール、D3 v7 を同梱）で、図・共有モジュール・本文を、担当ごとに互いのファイルに触れずに並行して作っています。最初に `README.md` を読んでください。図の契約、担当範囲、共通の操作部品、動かし方が書いてあります。

あなたの作業ブランチは `w1/l4-tilemap`（`s0/skeleton` から分岐）です。

## 仕事
`lib/tilemap.js` のスタブを実装します。47都道府県を同じ大きさの正方形のマスで並べた「タイルグリッド地図」をSVGで描く共有モジュールで、ページの3つの図（導入図、データ×スキーム対応表、色覚シミュレータ）が使います。公開する関数とその意味は、スタブの JSDoc と README に書かれているとおりです（シグネチャは変えません）。

- `render(el, { prefectures, fill, labels, ariaLabel })`：`prefectures` は `data/prefectures.json` を読み込んだオブジェクト全体です。各都道府県の `x`（列、0〜12）と `y`（行、0〜11）にマスを置きます。
- SVG は `viewBox` つきで、親要素の幅いっぱいに伸縮します。D3 は使わず、DOM のAPIだけで描きます（`deps` を受け取らないモジュールのため）。
- `labels` が真のとき、各マスに `short`（県名の略称）を表示します。文字色は、塗りの明るさ（sRGB の相対輝度を自前で計算）に応じて濃いグレーか白を選びます。幅390pxの画面でマスが小さくなり、文字が 11px 未満になる場合に備えて、`labels` には `'auto'` も受け付け、マスの表示サイズが足りないときは文字を出さないようにします（`ResizeObserver` で切り替え）。JSDoc にこの値を追記してください。
- 各マスには `<title>` で県名を付け、`data-code` 属性に都道府県コードを持たせます（図の側がホバー表示やテストに使います）。マスの間には細い隙間を空け、枠線は付けません。
- `update({ fill })` は、マスを作り直さずに色（と文字色）だけを更新します。`destroy()` は、作った要素と `ResizeObserver` を片付けます。
- 単体確認用に `lib/tilemap.demo.html` を作ります。座標が確定したデータが必要なので、下の座標表を使った確認用データを demo の中に持たせます（`data/prefectures.json` は別の担当が同時に確定させています。あなたは編集しません）。demo では、地方ごとにグレーの濃淡を変えた塗りと、ボタンで別の塗りに切り替える `update` の動作を見せます。

## 完了条件
1. `npm test` がすべて通る。`tests/tilemap.test.js` は、DOM を必要としない部分（座標からマスの位置を求める関数、塗りの色から文字色を選ぶ関数）を検査する。この2つは内部関数として切り出し、テスト用に export してよい（README の公開関数の一覧には加えない）。
2. Playwright はこの環境に導入済みです（`require('playwright')` がどのディレクトリからでも使え、`chromium.launch()` はオプション不要。ESモジュールからは `createRequire` で読み込めます）。`npm run serve` でサーバを起動し（ポート4173）、確認が終わったら止めます。 `lib/tilemap.demo.html` を幅1280pxと幅390pxで開き、47個のマスが重ならずに表示されること、横スクロールが出ないこと、幅1280pxでは県名が 11px 以上で表示され、幅390pxでは `'auto'` の指定で県名が消えること、`update` で色が変わること、コンソールエラーが0件であることを確かめる。
